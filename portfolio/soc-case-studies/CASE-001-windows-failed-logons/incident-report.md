# SOC L1 Case Report — CASE-001

**Classification:** Fictional tabletop exercise, *not a real incident or live test*.  
**Analyst:** Lorenzo Franzé (training portfolio)  
**Asset:** WIN-LAB-01 (fictional)  
**Period:** 2026-10-15 14:00–14:05 UTC (fictional timestamps)

## Alert description

An example event stream contains six Windows Security 4625 authentication failures for `lab-user`, followed by one 4624 logon success. All seven entries were **constructed for teaching purposes**.

## Evidence summary

| Source | Observed in exercise | Limitations |
|---|---|---|
| Synthetic CSV | Six 4625, one 4624 | Not generated by Windows or exported from Wazuh |
| Source address | 192.0.2.25 | Documentation-only address |
| Target user | lab-user | Fictional account |
| Endpoint context | Not available | No process, MFA, IP ownership, or user confirmation |

## Analyst reasoning

The sequence can be consistent with repeated password guesses, but also with a legitimate user correcting a password. No claim of account compromise is justified based on these events alone.

## Initial disposition

**Suspicious / needs validation** — insufficient evidence for a confirmed incident.

## Next steps for a real SOC

- Validate log fields, event origin and time synchronization.
- Confirm the account owner and whether the source device is expected.
- Check other targeted accounts, additional sign-ins, endpoint alerts and MFA evidence if available.
- Compare behavior with organization baselines and escalation criteria.
- Escalate promptly if critical assets or additional indicators raise confidence.

## Response

No account was disabled, host isolated, or credential reset: this was a simulated scenario, and no live actions were performed.

## ATT&CK

T1110 (Brute Force) — **possible interpretation only**, not confirmed.

## Lessons learned

A SOC L1 report must distinguish *observations*, *hypotheses*, *missing telemetry* and *recommended next actions*. A count of failed authentications is not a verdict.
